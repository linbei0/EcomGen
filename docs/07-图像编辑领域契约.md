# 图像编辑领域契约

本文定义连续图像编辑的领域对象、状态、不变量和 Agent 输出协议。它是 API、Worker、前端状态和数据库设计的共同边界。

## 目标

- 在当前生成结果上进行精确局部修改。
- 覆盖商品替换、场景调整、扩图和自然融合。
- 让用户通过自然语言、标注、涂抹和参考素材表达意图。
- 每次修改创建不可变的新 Output，支持继续修改、回退和分支。

## 核心原则

1. Agent 负责理解、分类和规划；应用负责坐标、遮罩、资产权限、版本关系和像素边界。
2. 用户不直接选择内部操作模式，Agent 生成简短可读的修改计划。
3. 高影响操作必须确认；低风险精确修改可以自动执行。
4. Provider 的 mask 只是生成指导，不代表未遮罩像素一定不变；精确模式必须经过服务端像素合成。
5. 原图和历史 Output 永不覆盖。
6. 项目记忆可以跨图片复用，编辑会话记忆只绑定当前分支。

## 操作类型

```ts
type EditOperation =
  | "PRECISE_INPAINT"
  | "PRODUCT_REPLACE"
  | "SCENE_ADJUST"
  | "OUTPAINT"
  | "NATURAL_FUSION";
```

| 操作 | 必要输入 | 默认保护策略 | 是否默认确认 |
| --- | --- | --- | --- |
| `PRECISE_INPAINT` | 目标遮罩或目标标注 | `PIXEL_LOCKED` | 否 |
| `PRODUCT_REPLACE` | 目标区域、参考商品素材 | `PROTECT_USER_MASK` | 是 |
| `SCENE_ADJUST` | 场景描述，可选遮罩 | `PROTECT_USER_MASK` | 是 |
| `OUTPAINT` | 新画布尺寸和方向 | 原图区域固定 | 是 |
| `NATURAL_FUSION` | 融合描述，可选遮罩 | `ALLOW_BROAD_CHANGE` | 是 |

## 编辑标注

标注文档使用源图内在像素坐标，不能保存浏览器 CSS 坐标。

```ts
type EditAnnotationDocument = {
  sourceWidth: number;
  sourceHeight: number;
  annotations: Array<{
    id: string;
    type: "rect" | "ellipse" | "arrow" | "text" | "freehand";
    points?: Array<{ x: number; y: number }>;
    bounds?: { x: number; y: number; width: number; height: number };
    text?: string;
    semanticRole?: "target" | "instruction" | "remove" | "add";
  }>;
  maskStrokes: Array<{
    mode: "add" | "erase" | "protect";
    size: number;
    points: Array<{ x: number; y: number }>;
  }>;
};
```

系统生成两个不可变中间文件：`edit-mask.png` 和 `protect-mask.png`。保护区域优先级高于编辑区域：

```text
effectiveEditMask = editMask - protectMask
```

## Agent 计划协议

```ts
type EditPlan = {
  operation: EditOperation;
  confidence: number;
  userSummary: string;
  prompt: string;
  targetAnnotationIds: string[];
  referenceAssetIds: string[];
  maskPolicy:
    | "USE_USER_MASK"
    | "USE_ANNOTATION_REGION"
    | "EXPAND_USER_MASK"
    | "FULL_SCENE";
  protectionPolicy:
    | "PIXEL_LOCKED"
    | "PROTECT_USER_MASK"
    | "ALLOW_BROAD_CHANGE";
  compositePolicy: "MASK_LOCKED" | "NATURAL_BLEND" | "OUTPAINT";
  providerRequirements: string[];
  requiresConfirmation: boolean;
  riskFlags: string[];
  memoryPatch?: {
    summary?: string;
    constraints?: string[];
  };
};
```

### 确定性校验

- Agent 只能引用输入中存在的标注 ID 和资产 ID。
- `PRODUCT_REPLACE` 没有参考资产时进入 `NEED_INPUT`，不能执行。
- `PRECISE_INPAINT` 没有目标区域时进入 `NEED_INPUT`。
- Provider 不支持计划要求的能力时返回明确的 `CAPABILITY_UNSUPPORTED`。
- 高影响操作未批准时不能进入生成阶段。

## 状态机

```text
DRAFT -> PLANNING -> PLAN_READY -> AWAITING_CONFIRMATION -> GENERATING -> SUCCEEDED
                         |                                      |
                         v                                      v
                    NEED_INPUT                                FAILED
```

规则：只有 `SUCCEEDED` 才创建新 Output；失败、取消或缺少输入都不能产生成功结果。

## Output 血缘

Output 增加以下字段：

```text
parentOutputId nullable
rootOutputId nullable
editSessionId nullable
editTurnId nullable
```

`generationSnapshot` 保存本次执行不可变事实：操作类型、源 Output、遮罩 hash、参考资产、Provider、模型、输入保真度和合成策略。

## 记忆边界

编辑会话记忆保存当前图片分支上的约束、用户偏好和最近结果；项目记忆保存商品事实、品牌规则和可复用素材。Agent 每轮由应用组装项目事实、会话摘要、最近回合和当前输入，不依赖模型内部的隐式长记忆作为唯一事实来源。

## 像素合成

`MASK_LOCKED` 模式下：

```text
result = generated * effectiveEditMask + source * (1 - effectiveEditMask)
```

`NATURAL_BLEND` 可以使用软遮罩和边缘羽化，但计划必须标记风险；`OUTPAINT` 只生成新增画布区域，原图区域固定。
