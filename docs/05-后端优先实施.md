# 后端优先实施

## 目标

先交付稳定、可测试、可供独立前端消费的 API 和 Worker。前端开始开发的唯一前置条件是 OpenAPI 契约、SSE 事件、错误模型和本地运行方式稳定。

## 第一阶段：契约与基础设施

1. 建立 pnpm workspace 与 `web/api/worker/packages` 目录边界。
2. 在 `packages/contracts` 定义 TypeBox Schema、枚举、错误模型和事件模型。
3. 固化 [openapi.yaml](openapi.yaml)；对其做 OpenAPI 校验。
4. 建立 Fastify 健康检查、统一错误返回、CORS、SSE 骨架和 SQLite migration。
5. 建立 Redis/BullMQ 队列、Worker 心跳和任务状态机。

验收：前端可以仅凭 OpenAPI 调用健康检查、创建项目、上传素材、读取项目；任一错误都符合统一错误模型。

## 第二阶段：商品项目与素材

1. 项目、变体、素材、Provider 配置的 CRUD。
2. 本地文件安全保存、缩略图生成、hash 和记账。
3. 变体与素材角色约束：每个分镜的 `variantScope` 只能是 `COMMON` 或已有变体 ID。
4. 任务事件经 SSE 实时推送，并可 REST 补拉。

验收：API 与 Worker 重启后，项目/素材/任务状态不丢失；前端可独立实现创建向导和素材库。

## 第三阶段：Pi 计划与分镜

1. 实现 Pi 的受限领域工具。
2. 加载 `ecom-details-image` 模板与平台规则包。
3. 实现“生成计划”“更新计划”“编辑分镜”任务。
4. 对 Agent 输出执行 Schema 校验；校验失败返回结构化错误，不写入半成品计划。

验收：同一输入可以生成包含 Style Lock、事实来源、模式、变体和风险的分镜计划；用户确认前不产生任何生图 job。

## 第四阶段：生图、审图与导出

1. 接入 OpenAI 兼容生图 Provider Adapter；同步和异步 Provider 均由 Worker 处理。
2. 实现单图生成、变体生成、重试、取消和任务恢复。
3. 实现最终版本选择、审图标记、预检和导出 job。
4. ZIP 内生成图片、manifest、审图检查表和可选详情页切片。

验收：浏览器关闭、API/Worker 重启后仍可恢复未完成任务；已完成 job 不重复提交给 Provider；导出内容可由 manifest 完整追溯。

## 前端交接门槛

后端 Agent 在交接前必须提供：

- 可校验的 `docs/openapi.yaml`；
- `docs/06-API接口契约.md` 的端点、状态机、SSE 和错误说明；
- 本地开发命令、环境变量说明、示例数据和可运行 API；
- 对所有关键端点的集成测试；
- 一个可用的 `curl`/HTTP 客户端示例集合；
- 不依赖前端代码的 Docker Compose 运行方式。

前端 Agent 不得读取数据库或 Redis，不得直接调用模型 Provider；所有状态均经 API 获取。
