# 平台策略

## 平台入口

产品只向用户展示两个目标：`国内平台` 与 `Amazon`。二者可同时选择。该选择影响分镜推荐、导出尺寸、命名和风险提示，而不是限制创意方向。

国内平台包含淘宝/天猫、京东和拼多多的共同视觉生产流程。它们不是同一套审核规则，因此后端必须把细节写成版本化覆写，不在 UI 强迫用户逐平台选择。

## 通用视觉策略

`ecom-details-image` 是 Prompt 策略内核。每套图必须：

- 先建立 Campaign Style Lock，再对每张图原样复用；
- 让每张图只回答一个购买问题；
- 对主体、画幅、镜头、产品占比、留白、文字和负面项做显式约束；
- 多图混合不同景别和角度，避免同质化；
- 将事实来源不明的文本标记为人工待核验。

## 国内平台覆写

- 优先生成 `1:1` 商品图，并可派生 `3:4` 竖版，不把方图简单裁切为竖图。
- 默认不出现二维码、联系方式、第三方平台标识、无关 Logo、竞品信息或不可证实的认证/数据。
- 淘宝/天猫的 `1:1`、`3:4` 图存在发布端分流与类目差异，策略包需保留版本和来源。[淘宝公告](https://open.fliggy.com/support/announcementDetail.htm?id=25721)
- 京东主图使用文字或图标时必须尊重商品主体区与元素安全区；价格结算信息、平台图标、竞品对比和夸大宣传属于高风险项。[京东规则](https://mtt.m.jd.com/article/articleView/180a744d-d813-4833-918f-8f632e0b68d7)
- 拼多多的首版使用国内通用档案，只显示“发布前请在当前类目规则中复核”，不宣称自动合规。

## Amazon 覆写

Amazon 的 `MAIN`、`PT01–PT08` 和 `SWCH` 是不同媒体属性，且约束取决于商品类型与 marketplace。[Amazon SP-API](https://developer-docs.amazon.com/sp-api/docs/submit-media)

| 槽位 | 策略 |
| --- | --- |
| `MAIN` | 严格主图：纯白背景、真实待售商品、无文字/徽章/水印/无关道具。优先使用主体像素保护模式。 |
| `PT01–PT08` | 角度、细节、场景、尺寸、包装和信息图；仍需匹配实际商品和套装。 |
| `SWCH` | 只在用户确认变体颜色/材质后生成。 |
| A+ / PDP | 作为详情页包，不与 `MAIN` 的限制混用。 |

## 规则包约定

每个规则项包含：`id`、`platformScope`、`assetScope`、`severity`、`condition`、`message`、`sourceUrl`、`verifiedAt`、`policyVersion`。导出 manifest 记录实际使用的策略版本。

高风险不自动替用户通过：系统允许查看和继续，但导出操作必须显式确认。损坏文件等技术错误则直接失败并展示原始原因。
