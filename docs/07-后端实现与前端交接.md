# 后端实现与前端交接

## 可直接对接的服务

API 默认地址是 `http://127.0.0.1:8787`，所有业务端点以 `/api/v1` 开头。机器可读契约仍以 [openapi.yaml](openapi.yaml) 为入口；前端实现前应以运行中的 API 为准，并在合并前将契约差异同步回来。

已实现：Provider 加密保存、项目和 SKU、素材上传、本地文件访问、上游 `ecom-details-image` 模板选择、Pi 规划任务、可编辑且需确认的分镜、OpenAI 兼容生图任务、输出审核、ZIP 导出、Redis/BullMQ 队列、跨 API/Worker 的 Redis Pub/Sub SSE。

未实现为成功路径的能力不会伪造结果：非 OpenAI Images API 的 `custom` 生图模型会以明确任务错误结束；没有 `PRODUCT_TRUTH` 素材的像素保护任务会失败；模型不可达时任务记录为 `FAILED` 并保留错误摘要。

## 前端调用顺序

1. 读取 `GET /ecom-templates`，展示用户可选择的上游套图模板；适配细节见 [08-ecom-details-image-适配说明.md](08-ecom-details-image-适配说明.md)。
2. `POST /providers` 保存一个或多个兼容服务及其模型能力。响应只有 `hasApiKey`，不回传密钥。
3. `POST /projects` 指定推理模型、生图模型、`DOMESTIC`/`AMAZON`、默认模式与商品事实。事实字段必须由用户或已有商品资料提供，前端不得让 Agent 猜测后静默写入。
4. `POST /projects/{projectId}/variants` 创建 SKU；再用 multipart `POST /projects/{projectId}/assets` 上传素材。上传字段为 `file`、`role`、可选 `variantId`。
5. `POST /projects/{projectId}/planning-jobs` 携带用户所选模板，随后订阅 `GET /events?projectId=...`。计划完成后 `GET /projects/{projectId}/storyboard`。
6. 用户编辑 `PATCH /storyboard-items/{itemId}`，确认后调用 `POST /projects/{projectId}/storyboard/confirm`。
7. 显式传入所选 `storyboardItemIds` 调用 `POST /projects/{projectId}/generation-jobs`；前端必须先展示数量和成本提示。
8. 使用 `PATCH /outputs/{outputId}/review` 标记结果，再创建 `POST /projects/{projectId}/export-jobs`。文件 URL 分别是 `/files/assets/{id}`、`/files/outputs/{id}`、`/files/exports/{id}`。

## 数据形状与事件

列表端点当前直接返回数组；项目详情返回 `{ ...project, variants, assets, storyboard, items, outputs, jobs }`。不要在前端直连 SQLite、Redis 或模型服务。

任务状态为 `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`、`CANCELLED`。SSE 事件为 `job.updated`、`storyboard.updated`、`output.created`、`export.updated`；事件只用于使查询失效，页面刷新状态必须由 REST 获取。

## 本地与 Docker

开发：复制 `.env.example` 为 `.env`，生成主密钥可用 `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`，然后分别运行 `pnpm dev:api` 和 `pnpm dev:worker`。Redis 使用已有本机实例。

面向直接使用者：在 `.env` 设置 `ECOMGEN_MASTER_KEY` 后运行 `docker compose up -d --build`。Compose 自带 Redis，SQLite 和上传/生成文件由具名卷持久化，不需要 MinIO 或 S3。
