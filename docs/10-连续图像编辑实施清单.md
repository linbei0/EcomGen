# 连续图像编辑实施清单

本文按可交付闭环拆分工作，目标是先建立可靠的精确修改基础，再逐步覆盖商品替换、场景调整、扩图和自然融合。

## 阶段一：精确局部修改闭环

### 契约与持久化

- [ ] 在 `packages/contracts` 增加 EditOperation、EditPlan、EditSession、EditTurn 类型。
- [ ] 在 `packages/core` 增加 `edit_sessions`、`edit_turns`、`edit_plans` 表。
- [ ] 为 `outputs` 增加父子血缘和编辑关联字段。
- [ ] 为编辑中间文件增加 `edits/{projectId}/{sessionId}/{turnId}` 存储路径。
- [ ] 为旧 Output 保留空的血缘字段，执行一次显式数据库迁移。

### API

- [ ] 创建编辑会话。
- [ ] 查询编辑会话和版本关系。
- [ ] 以 multipart 提交编辑回合。
- [ ] 查询计划和回合状态。
- [ ] 批准高影响计划。
- [ ] 选择历史版本。
- [ ] 增加幂等指纹和 projectId 归属校验。
- [ ] 同步 `openapi.yaml` 和接口说明。

### Worker 与 Agent

- [ ] 新增 `edit_plan` 和 `edit_generate` 任务类型。
- [ ] 在 Pi Agent 适配器中增加结构化 edit planner。
- [ ] 增加计划确定性校验器。
- [ ] 校验 mask、protect mask 和源 Output 尺寸。
- [ ] Provider 生成失败时不创建成功 Output。
- [ ] 成功后更新会话 currentOutputId 和记忆摘要。

### Provider 与像素处理

- [ ] 扩展图像 Provider 能力描述：mask、参考图、输入保真度、扩图、自然融合。
- [ ] 支持 source image、reference images 和 mask 的明确输入结构。
- [ ] 对不支持 mask edit 的 Provider 返回 `CAPABILITY_UNSUPPORTED`。
- [ ] 实现 `MASK_LOCKED` 服务端像素合成。
- [ ] 增加合成后的尺寸、格式和 hash 校验。

### 前端工作台

- [ ] 在 ReviewStage 增加“编辑图片”入口。
- [ ] 建立 `EditImageWorkspace`，画布与 Agent 面板分栏。
- [ ] 实现矩形、椭圆、箭头、文字标注。
- [ ] 实现涂抹、擦除和保护遮罩。
- [ ] 实现局部撤销、重做、缩放和选中态。
- [ ] 使用源图内在坐标序列化标注。
- [ ] 增加计划摘要、确认和缺少输入状态。
- [ ] 生成完成后提供“继续修改”和版本切换。

## 阶段二：商品替换与连续记忆

- [x] 参考商品选择器只在计划需要时出现。
- [x] 商品替换强制要求参考资产。
- [x] 增加会话摘要和约束记忆编辑。
- [x] 支持从任意历史 Output 创建新分支。
- [x] 增加版本对比和当前版本标识。

## 阶段三：场景调整、自然融合和扩图

- [ ] 增加场景级操作和风险确认。
- [ ] 增加软遮罩、边缘羽化和自然融合策略。
- [ ] 增加画布扩展方向、尺寸和 outpaint mask。
- [ ] 增加多参考图和 Provider 路由。
- [ ] 对大范围修改显示明确影响范围。

## 视觉与交互验收

- [ ] 画布是第一视觉焦点，工具栏不抢主视觉。
- [ ] 只使用一个主操作强调色，避免 AI 紫色渐变和发光装饰。
- [ ] 工具栏使用图标和 tooltip，文字仅用于清晰命令。
- [ ] 高风险确认是上下文提示，不使用复杂模式表单。
- [ ] 加载态使用与画布形状匹配的骨架或局部进度，不使用孤立 spinner。
- [ ] 错误信息在当前回合附近显示，并明确修复动作。
- [ ] 版本关系使用轻量时间线或树，不嵌套卡片。
- [ ] 键盘焦点、对比度、缩放和窄窗口布局通过检查。
- [ ] 支持 reduced motion，动画只用于状态转场和操作反馈。

## 测试验收

- [ ] 遮罩外像素锁定测试。
- [ ] protect mask 覆盖 edit mask 的优先级测试。
- [ ] 输出父子版本和历史分支测试。
- [ ] 重复提交幂等测试。
- [ ] 资产越权和遮罩尺寸校验测试。
- [ ] Agent 非法 annotation ID 拒绝测试。
- [ ] Provider 能力不足的明确错误测试。
- [x] 连续修改默认使用当前 Output 测试。
- [x] 商品替换缺少参考图进入 `NEED_INPUT` 测试。
- [ ] Mock E2E 覆盖计划、确认、生成和版本刷新。

## 建议实施顺序

```text
契约/迁移
  -> API 会话与回合
  -> Agent 计划
  -> Provider mask edit
  -> 像素合成
  -> 前端画布
  -> 连续版本
  -> 商品替换
  -> 场景/扩图/融合
```

每一步都必须保留可运行的端到端闭环，不提前加入无法验证的“智能降级”。
