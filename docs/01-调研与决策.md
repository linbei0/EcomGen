# 调研与决策

## 产品判断

EcomGen 不是通用聊天生图工具，也不是企业协作画布。它要把个人卖家的不完整商品素材组织为一个可追溯项目：平台目标、图片类型、商品变体、风格参考、分镜、生成版本和导出结果都属于同一商品款。

最重要的价值是“成套且可控”，而非仅提高单张图片的美观度。

## 研究依据

| 来源 | 可验证能力 | 纳入 EcomGen 的结论 |
| --- | --- | --- |
| [ecom-details-image](https://github.com/liangdabiao/ecom-details-image) | 25 个场景模板、转化驱动力诊断、Campaign Style Lock、主图/PDP 序列、参考图和负面约束。 | 作为唯一的 Prompt 与分镜策略内核；Web 层将其变为可编辑项目对象。 |
| [AI Species](https://ai-species.com/) | 平台/风格选择、上传商品图、一次生成套图、详情页和任务队列。 | 入口应低门槛，任务状态必须可见。 |
| [咖图 AI](https://www.katuai.cn/) | Plan/Ask、多模型、参考图、批量任务、协作画布。 | 采用“先规划再生成”，不复制协作画布和企业工作流。 |
| [MegaViews Commerce](https://megaviews.ai/commerce) | 前端公开资源显示 Commerce 有主图、详情批量图、图生图、商品视频、素材中心和任务中心。 | 素材、任务、失败原因和重试是核心产品对象；视频不进首版。 |
| [Photoroom Product Fixer](https://help.photoroom.com/en/articles/15289495-use-product-fixer-to-improve-image-fidelity-on-uploaded-files-web-app) | 使用真实商品图和局部区域修复 AI 输出的商品偏差。 | “像素级”必须实现为主体像素保护，而不能承诺生成新角度后仍像素不变。 |

## 不可变决策

| 决策 | 结论 |
| --- | --- |
| 项目单位 | 一个项目 = 一个 SPU，可包含多个 SKU 变体。 |
| 平台入口 | 只显示“国内平台”和“Amazon”，可多选。 |
| 图片选择 | 用户显式选择，或让 Agent 推荐；推荐计划可编辑且必须确认。 |
| 视觉模式 | 创意模式、主体像素保护模式；项目默认值可由单图覆盖。 |
| 商品事实 | 不完整输入允许继续；创意卖点草案允许，但不得编造可核验事实。 |
| 模型 | 用户分别选择推理模型和生图模型；Pi 支持多 Provider。 |
| 编辑 | 首版只支持重生成、修改要求、替换参考图和切换模式。 |
| 开发结构 | 同一仓库内前端、后端、Worker 独立开发；后端先行，契约先行。 |

## 平台策略判断

国内平台的制作流程可以共用，但规则不能被视为相同。淘宝存在 `1:1` 和 `3:4` 主图分流；京东有商品主体区和元素安全区等约束；Amazon 则把 `MAIN`、附图和色卡当作不同媒体属性。[淘宝公告](https://open.fliggy.com/support/announcementDetail.htm?id=25721) [京东规则](https://mtt.m.jd.com/article/articleView/180a744d-d813-4833-918f-8f632e0b68d7) [Amazon SP-API](https://developer-docs.amazon.com/sp-api/docs/submit-media)

因此 UI 用两个平台目标降低认知成本，后端仍把导出规则做成版本化策略包，并在导出前展示待人工复核项。
