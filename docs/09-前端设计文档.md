## 1. 竞品调研结论

调研对象：AI Species（ai-species.com）、咖图AI（katuai.cn）、Megaviews Commerce、Flair.ai、Pebblely、Mokker。

| 竞品 | 模式 | 值得借鉴 | 不适合照搬 |
| --- | --- | --- | --- |
| AI Species | 单页表单流，上传→选模式/平台/风格→一键出 9 张 | 成本前置（按钮上直接写"生成图像 消耗 199 积分"）；决策链极短 | 黑盒出图，无分镜概念 |
| 咖图AI | 节点式无限画布 + 模板市场 | 模板视觉化运营 | 学习成本高，面向专业用户，个人卖家不适用 |
| Flair.ai | 拖拽画布 + 3D 道具摆场景 | 工作室级视觉质感 | 自由画布与首版边界冲突（明确不做自由画布） |
| Pebblely | 上传→模板画廊（100+ 视觉缩略图）→生成 | 模板必须画廊化，禁止下拉框选模板；批量生成 | 无 SKU 变体概念 |
| Mokker | 三步（上传抠图→选模板→出图） | Moodboard 参考图驱动风格；色彩控制 | 无审核与重试闭环 |

四条共同规律，全部采纳：

1. **成本/消耗直接写在生成动作上**，不藏在账单页。
2. **模板选择是视觉画廊**，不是表单字段。
3. **上传是第一动作**，零门槛。
4. **工作台类产品普遍深色工作室质感 + 大留白排版**，让商品图成为唯一高饱和元素。

EcomGen 的差异化（前端必须放大，而不是藏起来的）：

- 分镜可编辑、可确认，Agent 不自动提交生图；
- SKU 变体隔离，禁止跨 SKU 混图是界面级可见约束；
- 创意 / 主体像素保护双模式，模式语义要在每个分镜上可读；
- 事实约束：不编造价格、规格、认证、功效，`verifiedFacts` / `prohibitedClaims` 在界面有一等公民位置。

## 2. 设计目标与 Design Read

### 2.1 Design Read

- **产品**：本地优先的电商套图工作台，用户是个人卖家，不是设计师。
- **一页必须回答的问题**："我的套图现在进行到哪一步，下一步要我做什么"。
- **情绪**：暗房里的工作台——克制、专注、可预期；商品图是房间里唯一的光。
- **反目标**：不做营销落地页、不做节点画布、不做 AI 产品常见的紫蓝渐变 + 玻璃拟态套路。

### 2.2 设计拨杆（依据 `.agents/skills/design-taste-frontend`）

| 拨杆 | 值 | 理由 |
| --- | --- | --- |
| DESIGN_VARIANCE | 6 | 工具属性要求布局稳定，但首页画廊、空态、阶段切换允许编辑化排版 |
| MOTION_INTENSITY | 5 | 动效只服务状态转换与反馈（显影、确认、失效刷新），不做装饰性视差 |
| VISUAL_DENSITY | 6 | 工作台信息密度高于营销站，但每个面板保留呼吸留白；数据区密度高、操作区密度低 |

质量基线遵循项目技能 `design-taste-frontend` 的全部纪律：最多 1 个强调色且饱和度 < 80%、禁纯黑纯白、禁紫蓝渐变、动效必须有动机且只动 transform/opacity、尊重 `prefers-reduced-motion`、z-index 克制并文档化（见 6.6）、LCP < 2.5s / INP < 200ms / CLS < 0.1、不展示假数据与假精确数字。

品牌与视觉资产生产流程参考 `.agents/skills/brandkit`；当前环境无图像生成工具，空态一律用排版 + 网格构成，不使用占位假图。

## 3. 设计叙事主线：暗房 — 显影 — 灯箱

整个应用是一间暗房（darkroom studio），三个阶段意象贯穿六个业务阶段：

| 意象 | 对应业务 | 视觉转译 |
| --- | --- | --- |
| 暗房 | 素材、规划、分镜编辑 | 全场最低的亮度与饱和；界面退后，素材缩略图是唯一光源 |
| 显影 | 生成中 | 输出卡片从低亮度模糊态"显影"为清晰图（opacity + scale，不动 layout）；进度是显影进度而非普通 loading |
| 灯箱 | 审核、导出 | 审图网格整体提亮一档，SELECTED 的图带一圈暖色描边，像灯箱上被选中的底片 |

这条主线决定了：强调色必须是暖色（暗房安全灯 / 灯箱钨丝的琥珀色），全站只有一个强调色；蓝色只允许出现在 AntD 组件内部不可控处并被主题压到最低。

## 4. 技术栈与工程结构

### 4.1 选型（均已确认）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 构建 | Vite + React 19 + TypeScript（strict, NodeNext 风格导入） | 与仓库现有 TS 约定一致 |
| UI 库 | **Ant Design v6** + 深度主题定制 | 02 文档明确约定；其 Steps/Upload/Form/Drawer/Tabs/Image Preview/Progress 恰好覆盖核心闭环。备选 Arco（字节，设计语言同样强势但社区主题能力弱于 AntD）、Mantine（hooks 优秀但 Upload/Image Preview 需自补）、MUI（视觉风格与深色工作室方向冲突、定制成本高）均不如 AntD 契合 |
| 图标 | `lucide-react`（全站唯一图标源，**禁用** `@ant-design/icons` 与 emoji） | 用户强制约束 |
| 数据 | TanStack Query v5 | REST 是状态真相 |
| API Client | **openapi-typescript**（生成类型）+ **openapi-fetch**（运行时） | 纯类型生成 + 轻量 fetch 包装，hooks 手写，无额外代码生成器 |
| 动效 | `motion`（`import { motion } from "motion/react"`） | framer-motion 后继包 |
| 路由 | react-router v7 | 路由极少（见第 5 节），不需要类型安全路由器的复杂度 |
| 测试 | Vitest + @testing-library/react + msw + jsdom | 与仓库 vitest ^3.1.2 对齐 |
| 样式 | AntD cssinjs 主题 + 全局 `tokens.css` CSS 变量 + CSS Modules（自定义组件） | 不设 tailwind，避免与 AntD 主题双轨 |

不引入全局状态库（zustand/redux）：服务端状态全部归 TanStack Query；UI 状态用 React state + URL search params（当前阶段、选中分镜、灯箱打开态都可入 URL，天然可刷新恢复）。

## 5. 信息架构与路由

无营销落地页。两条路由，其余全部是路由内的状态：

| 路由 | 页面 | 内容 |
| --- | --- | --- |
| `/` | 项目画廊 | 项目卡片网格 + 强视觉空态 + 新建项目入口 + 全局设置入口 |
| `/projects/$projectId?stage=…` | 项目工作台 | 单页工作台，顶部阶段条，三栏布局 |

- `stage` ∈ `assets | plan | storyboard | generate | review | export`，写入 URL search param，刷新/分享可恢复；非法值回退到推导出的当前阶段。
- 阶段**可自由导航**，不强制线性向导；阶段条同时显示推导出的"进行到哪一步"（由数据推导：有素材→素材完成；有 storyboard→规划完成；`CONFIRMED`→分镜完成；有 outputs→生成完成；有 SELECTED→审核完成；有 SUCCEEDED export→导出完成）。
- Provider 配置在**全局设置抽屉**（首页与工作台顶栏均可打开），不占路由。无 Provider 时创建项目向导在模型选择处给出内联引导，不打断流程把用户踢走。
- 弹层清单（全部 AntD Modal/Drawer 封装，z-index 见 6.6）：设置抽屉、创建项目向导、生成确认弹窗、灯箱审图、导出弹窗。

工作台三栏（遵循 02 文档布局约定）：

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：← 项目名 · 阶段条 · 任务状态 pill · 设置 · 导出入口      │
├──────────┬──────────────────────────────────┬────────────────┤
│ 左栏 260px│ 中栏（弹性）                       │ 右栏 320px      │
│ SPU 信息  │ 当前阶段主区（素材库/规划/分镜板/   │ 检视器：选中项  │
│ SKU 变体  │ 生成进度/审图网格/导出）           │ 详情与编辑     │
│ 素材导航  │                                  │                │
└──────────┴──────────────────────────────────┴────────────────┘
```

1280px 以下右栏改为覆盖式 Drawer，桌面优先最低支持 1280×800。

## 6. 设计系统

### 6.1 色彩 tokens（`design/tokens.css`）

遵守"最多 1 个强调色、禁纯黑纯白、饱和度 < 80%"：

```css
:root {
  /* 背景：暖调 off-black 阶梯 */

  --bg-2: #1a1a1e;   /* 抬升面（卡片、输入） */
  --bg-3: #222227;   /* 悬停/覆盖 */
  --bg-lightbox: #17171a; /* 灯箱模式的中栏基底（提亮一档） */

  /* 描边 */
  --line-1: rgba(237, 236, 230, 0.08);
  --line-2: rgba(237, 236, 230, 0.16);

  /* 文本：暖调 off-white */
  --text-1: #edece6;
  --text-2: #a6a49c;
  --text-3: #6e6c66;

  /* 唯一强调色：钨丝琥珀，HSL(39,66%,55%)，饱和度 <80% */
  --accent: #d9a441;
  --accent-hover: #e4b45a;
  --accent-active: #c2902f;
  --accent-subtle: rgba(217, 164, 65, 0.12);
  --accent-line: rgba(217, 164, 65, 0.4);

  /* 语义色（全部降饱和，仅表状态，不作装饰） */
  --success: #5fa87c;
  --warning: #d98e41;
  --danger:  #d95f4e;
  --info:    var(--accent);

  /* 模式标识不用颜色区分（保持单强调色纪律），用图标+文字：
     CREATIVE = Sparkles 图标，PIXEL_PROTECTED = ShieldCheck 图标 */

  --radius-s: 6px; --radius-m: 10px; --radius-l: 14px;
```

噪点/颗粒：仅一层 `position: fixed; pointer-events: none` 的伪元素，SVG feTurbulence data-URI，opacity 0.03，仅铺在 `--bg-0` 上，不进入任何面板内部。

### 6.2 字体与排版

| 角色 | 字体 | 说明 |
| --- | --- | --- |
| 展示（Display） | **得意黑 Smiley Sans**（OFL，自托管 woff2，按用到的汉字子集化） | 阶段名、空态大标题、项目名、数字大字。斜体骨架自带动势，契合"显影"叙事 |
| 正文 | `system-ui` 中文栈：`-apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif` | 工具正文用系统字保证可读性与零加载成本 |
| 等宽 | `"JetBrains Mono", ui-monospace, Consolas, monospace`（自托管子集） | Prompt、JSON、请求 ID、指纹 |

- 字体预算：两个子集化 woff2 合计 ≤ 200KB，`font-display: swap`。
- 字阶：Display 30/38（letter-spacing 0.01em）、Title 18/26、Body 13/20（AntD `fontSize` 13，桌面工具密度）、Caption 12/18。
- 数字用等宽或 `font-variant-numeric: tabular-nums`，成本/数量位对齐。
- 不使用 serif、不使用 italic 装饰（规避 descender 裁切问题）。

### 6.3 间距与栅格

- 4px 基网；面板内边距 16/20，栏间距 1px 描边而非空隙（工作台是连续平面）。
- 中栏网格：素材/审图用 `repeat(auto-fill, minmax(180px, 1fr))`，分镜卡用 `minmax(280px, 1fr)`。
- 反居中纪律：文本一律左对齐；空态的"居中式构图"每屏最多一处。

### 6.4 图标

全站 `lucide-react`，统一 `size={16} strokeWidth={1.75}`（导航/操作）、`20`（空态）。语义映射固定：

| 语义 | 图标 |
| --- | --- |
| 品牌/logo | `Aperture` |
| 素材 | `Images`；上传 `Upload` |
| 规划 | `ListTree` |
| 分镜 | `Clapperboard` |
| 生成 | `Wand2`；创意模式 `Sparkles` |
| 像素保护 | `ShieldCheck` |
| 审核 | `SquareCheckBig`；灯箱 `Maximize2` |
| 导出 | `PackageOpen`；下载 `Download` |
| 设置/Provider | `Settings2`；连通测试 `PlugZap` |
| 风险/事实 | `TriangleAlert` / `BadgeCheck` |
| 任务状态 | 运行 `LoaderCircle`（旋转）、失败 `CircleX`、取消 `CircleSlash` |

### 6.5 动效规范（`design/motion.ts`）

```ts
export const ease = {
  standard: [0.22, 1, 0.36, 1],   // 主缓动
  enter:    [0.16, 1, 0.3, 1],
} as const;
export const dur = { instant: 0.12, fast: 0.2, base: 0.32 } as const;
export const stagger = 0.024;      // 网格入场阶梯
```

有动机的动效清单（除此之外**不允许**新增动画）：

| 动效 | 动机 | 实现 |
| --- | --- | --- |
| 显影 | 新 Output 产生（状态转换） | 卡片从 `opacity 0 / blur(8px) / scale 0.98` → 清晰，600ms，仅 transform/opacity/filter |
| 网格入场 | 阶段切换后的内容到达 | `AnimatePresence` + stagger，y 8px + opacity |
| 选中描边 | 审核选择（反馈） | outline 颜色 + 2px 扩散，120ms |
| 阶段条进度 | 层级导航 | 指示器 layoutId 滑动 |
| 面板失效刷新 | SSE 触发缓存失效后数据替换 | 内容 cross-fade 150ms，不闪烁骨架 |
| 按钮按压 | 反馈 | scale 0.98，100ms |

纪律：只动 `transform/opacity/filter`；连续值用 `useMotionValue`；滚动监听用 IntersectionObserver（禁止 window scroll listener）；全局 `prefers-reduced-motion` 时全部降级为 0ms 即时切换（motion 的 `MotionConfig reducedMotion="user"`）。

### 6.6 z-index 与层级（文档化，禁止随意加码）

| 层 | 值 | 用途 |
| --- | --- | --- |
| base | 0 | 常规流 |
| sticky | 10 | 顶栏、阶段内工具条 |
| overlay | 100 | 右栏移动 Drawer、下拉 |
| drawer | 500 | 设置抽屉（AntD Drawer 对齐定制） |

## 7. 核心闭环交互设计

每阶段给出：目标 / 布局与组件 / 关键交互 / API / 状态与异常 / 空态。通用纪律：

- **成本规约**（`lib/cost.ts`）：`estimatedCost`/`actualCost` 防御式读取（契约仅 `object|null`）。仅当对象含明确 `status` 且为已知货币金额字段时展示数值；`status === "UNKNOWN"`、为 `null` 或字段缺失时，一律展示 **"费用由 Provider 决定，当前无法预估"**。任何位置禁止展示推测金额、禁止展示"约 ¥0.00"式假精确数字。
- **数量规约**：默认每个分镜仅生成 1 张；生成数量 = 用户显式勾选的分镜数，界面不出现"批量 ×N"的隐式放大。
- **模式规约**：项目有 `defaultMode`，每个分镜可覆盖；`PIXEL_PROTECTED` 的分镜卡显示 ShieldCheck 徽标与提示"仅使用同范围 PRODUCT_TRUTH 素材，保留主体像素"；缺少合规素材时按后端失败状态如实展示，不得伪装成功。
- **事实规约**：`verifiedFacts`/`prohibitedClaims` 在分镜检视器中只读展示；`factClaims`（`object[]`，契约未细化）按键值对只读渲染，不臆测结构、不可编辑。
- 所有错误经 `ApiError` 规范化后按 8.4 的 code 映射呈现，一律带 `requestId`（可复制）。

### 7.4 阶段二：规划

- **中栏**：左侧"规划意图"面板——图片类型回顾（chips，可回到向导心智但不在此改）、`userInstruction` 文本域（≤4000 字，带字数统计）、`allowAgentRecommendations` 开关（默认开，文案"允许 Pi 补充推荐分镜"）；右侧为规划产出摘要区。
- **提交**：`POST planning-jobs`，body `imageTypes`（来自项目创建时选择的模板，用户在此可增删勾选，至少 1 个）。提交后该面板锁定为只读摘要 + 进度。
- **进度**：Job 卡片显示 `QUEUED/RUNNING` + `progress`（0-100）+ 阶段文案（"Pi 正在规划分镜"）；SSE `job.updated` 仅触发失效，UI 以重新查询的 REST 数据渲染；`FAILED` 显示 `error.message` + `requestId` + 重试按钮（`retryable` 为 true 时）。

- **API**：`POST /projects/{id}/planning-jobs`、`GET /jobs/{id}`、失效源 `job.updated`。
- **空态/引导**：若无素材，面板顶部提示"未上传素材也可以规划，但像素保护分镜需要 PRODUCT_TRUTH 素材才能生成"。

### 7.5 阶段三：分镜（可编辑、需确认）

本阶段是差异化核心，投入最高的设计与测试权重。

- **中栏·分镜板**：`GET storyboard` 渲染卡片网格。卡片内容：缩略占位区（生成前为排版块：`assetType` Display 字 + 模式图标）、`assetType` 标题、`variantScope` 标签（"通用"或变体名，**强视觉约束色框**，提示不可跨 SKU 混图）、模式徽标（Sparkles/ShieldCheck）、`status` pill、`riskFlags` 非空时 `TriangleAlert` 计数角标。
- **右栏·检视器**（选中卡片时）：`assetType`（Select，选项来自 25 个模板 ID）、`variantScope`（Select：COMMON + 变体列表）、`mode`（segmented，切到 `PIXEL_PROTECTED` 时即时提示素材要求）、`promptInstruction`（TextArea 等宽字体，自动高度）、`factClaims` 只读键值列表、`riskFlags` 警告列表。编辑即 `PATCH /storyboard-items/{itemId}`（防抖 600ms，保存态行内指示；`CONFIRMED` 后不可编辑， PATCH 409/校验错误时回滚并提示）。
- **确认条**：中栏底部吸附条——"N 个分镜 · 创意 x / 像素保护 y" + `确认分镜` 按钮（强调色）。点击调 `POST storyboard/confirm`（带 `version`）。**409 CONFLICT**：toast"分镜已被其他操作更新"，自动 `GET storyboard` 刷新并要求重确认；成功后阶段条"分镜"置完成，锁定编辑，引导进入生成。
- **动效**：确认瞬间分镜板整体做一次 200ms 的"锁定"沉降（opacity 0.96→1 + 描边转细），传达状态转换。
- **API**：`GET /projects/{id}/storyboard`、`PATCH /storyboard-items/{itemId}`、`POST /projects/{id}/storyboard/confirm`、失效源 `storyboard.updated`。

### 7.6 阶段四：生成

- **选择模型**：分镜板进入选择态——每张卡带 checkbox（仅 `CONFIRMED` 分镜可选，已 `GENERATED` 的可勾选重试场景见下）；"全选未生成"快捷操作。**不存在任何默认全选/隐式提交**。
- **生成操作条**（中栏底部吸附，有选中项时出现）：`Wand2 生成 M 张` + 模式统计 + `费用提示`（`CostHint` 组件：7.6.1）。M = 勾选分镜数（每分镜 1 张）。
- **7.6.1 确认弹窗**（点击生成后必现）：清单表格（分镜 × 模式 × 变体范围）、总张数 M、Provider/模型名、费用区——严格按成本规约渲染；确认按钮文案 `确认生成 M 张`。勾选 revision 选项（`revision` 可选，针对已生成分镜重新出图）仅在含已生成分镜时出现。
- **提交**：`POST generation-jobs`，body 显式 `storyboardItemIds[]`（排序后参与指纹计算，见 8.5）；重复点击/刷新重提同指纹请求由后端去重复用任务，前端对"返回既有任务"与"新建任务"同样渲染。
- **进行中**：中栏切换为任务视图——Job 头卡（状态、`progress`、Provider/模型、可 `取消` 按钮，`cancelRequested` 后置为"取消中"禁用）+ 输出网格：`output.created` 事件触发失效，新 Output 以"显影"动效落位到其分镜卡位置；`FAILED` 展示错误与 `retry`（`retryable`）；取消是"请求取消"，状态以后端为准。
- **API**：`POST /projects/{id}/generation-jobs`、`GET /jobs/{id}`、`POST /jobs/{id}/cancel`、`POST /jobs/{id}/retry`、失效源 `job.updated`、`output.created`。

### 7.7 阶段五：审核（灯箱）

- **中栏切灯箱模式**：基底提亮至 `--bg-lightbox`，其余面板压暗，隐喻"把底片放上灯箱"。
- **网格**：Output 大卡片（minmax 220px），悬停浮出操作条：`SquareCheckBig 选入` / `CircleSlash 淘汰` / `Maximize2 灯箱`。`reviewDecision` 状态：SELECTED = 琥珀描边 + 角标；REJECTED = 降透明度 40% + 删除线感；NEEDS_REVIEW/未审 = 中性。操作即 `PATCH /outputs/{outputId}/review`（乐观更新 + 失败回滚）。
- **分组**：按分镜分组（每组标题 = assetType + variantScope），每组内按 `createdAt`；每个分镜下同一变体范围的多张图并排，方便"这套留哪张"的对比。
- **灯箱大图**：AntD Image Preview 定制 Modal——左侧大图，右侧信息列（分镜、模式、Prompt、决策 segmented、重试入口"用此分镜重新生成"→ 跳生成阶段并预选该分镜）。
- **批量操作**：选中多张后底部吸附条支持批量选入/淘汰。
- **API**：`PATCH /outputs/{outputId}/review`、输出列表来自项目详情嵌套（见 13.1/13.2）、失效源 `output.created`。
- **空态**：无 Output 时引导回生成阶段，不显示假网格。

### 7.8 阶段六：导出

- **导出弹窗/面板**：已选 Output 计数（仅 `SELECTED` 可导出，NEEDS_REVIEW/REJECTED 不计入，UI 过滤并说明）、`platformTargets` 勾选（默认沿用项目设置）、`includeDetailPageSlices` 开关（默认关）、费用/大小不做预估（不展示假数字）。
- **提交**：`POST export-jobs`（`outputIds[]` 显式列出）→ 任务卡（`QUEUED/RUNNING/SUCCEEDED/FAILED` + progress）。
- **下载**：`SUCCEEDED` 后显示 `下载 ZIP` 按钮，URL 优先 `Export.downloadUrl`，为空回退 `GET /files/exports/{id}`（见 13.6）；历史导出列表（时间、平台、张数、状态）。
- **API**：`POST /projects/{id}/export-jobs`、`GET /exports/{id}`、`GET /files/exports/{id}`、失效源 `export.updated`。

## 8. API Client 架构

### 8.1 类型生成

```jsonc
// apps/web/package.json scripts
"gen:api": "openapi-typescript ../../docs/openapi.yaml -o src/api/schema.d.ts"
```

`schema.d.ts` 提交入库；CI/提交前以 `pnpm gen:api` + `git diff --exit-code` 保证与契约同步。契约变更 → 重新生成 → 类型错误即前端改造清单。**禁止手写与契约平行的类型定义**。

### 8.2 Client 与配置

```ts
// config/env.ts
export const API_BASE_URL =
  import.meta.env.VITE_API_BASE_URL ?? "http://127.0.0.1:8787/api/v1";
// api/client.ts
export const api = createClient<paths>({ baseUrl: API_BASE_URL });
api.use(errorMiddleware); // 见 8.4
```

- `VITE_API_BASE_URL` 为唯一配置项；浏览器**只**与该源通信，绝无 Redis/SQLite/Provider 直连。
- CORS 待联调验证（13.8）；失败时的兜底是 Vite dev proxy（`server.proxy: { "/api": "http://127.0.0.1:8787" }`，此时 `VITE_API_BASE_URL=/api/v1`），不因此改后端。
- multipart 上传直接给 openapi-fetch 传 `FormData`（契约已声明 `multipart/form-data`）。

### 8.3 Query key 工厂（`api/queryKeys.ts`）

```ts
export const qk = {
  health: ["health"] as const,
  templates: ["ecom-templates"] as const,
  providers: ["providers"] as const,
  projects: ["projects"] as const,
  project: (id: string) => ["projects", id] as const,          // 详情含嵌套资源
  storyboard: (id: string) => ["projects", id, "storyboard"] as const,
  job: (id: string) => ["jobs", id] as const,
  exports: (id: string) => ["projects", id, "exports"] as const,
};
```

资源 hook 一律薄封装：`useProviders/useCreateProvider/.../useConfirmStoryboard/useCreateGenerationJob/useReviewOutput/useCreateExportJob`，mutation 的 `onSuccess` 精准失效对应 key。4xx 不重试；5xx/网络错误重试 2 次（指数退避）；`staleTime`：模板 10min，其余 30s；SSE 订阅中的项目工作页面 `refetchOnWindowFocus: true`。

### 8.4 错误规范化与 code 映射（`api/errors.ts`）

中间件把 `{error:{code,message,details,requestId}}` 包装为 `ApiError` 抛出；UI 只按下表分支：

| code | UI 行为 |
| --- | --- |
| `VALIDATION_ERROR` | 表单场景映射 `details` 到字段错误；否则 toast |
| `NOT_FOUND` | 详情页 → 404 视图；列表内 → toast + 失效列表 |
| `CONFLICT` | 分镜确认冲突：自动刷新 storyboard + 提示重确认；其余：提示资源已变化 |
| `CAPABILITY_UNSUPPORTED` | 模型选择前置拦截的兜底：指出缺少的能力标签 |
| `RATE_LIMITED` | toast"请求过于频繁"，附重试倒计时（若有 details） |
| `PROVIDER_ERROR` | 任务卡/面板内错误块：message + requestId + "检查 Provider 配置"入口 |
| `INTERNAL_ERROR` | 通用错误块 + requestId（一键复制） |

### 8.5 幂等与请求指纹（`api/fingerprint.ts`）

- 创建类 POST（planning/generation/export）计算稳定指纹：`sha256(canonicalJson({type, projectId, itemIds: sort(…), revision, …}))`（WebCrypto，hex）。
- 双击、断线重试、页面刷新后的重复提交携带同一指纹，后端复用 `QUEUED/RUNNING/SUCCEEDED` 任务；前端对"复用返回"无感渲染。
- 指纹字段名与位置（body 字段或 header）契约未声明 → 见 13.11，联调前按 body 可选字段 `requestFingerprint` 发送并容忍校验错误。

### 8.6 SSE（`api/sse.ts`）

- 工作台页挂载时建立单条 `EventSource(`${API_BASE_URL}/events?projectId=${id}`)`，卸载关闭；自动重连（EventSource 原生）+ 连接状态指示（顶栏小圆点：已连接/重连中）。
- **不解析 payload**（契约未定义结构，见 13.10），仅按事件名失效：

| 事件 | 失效 |
| --- | --- |
| `connected` | 无（置连接态） |
| `job.updated` | `qk.project(id)`、`qk.exports(id)`；当前任务视图额外失效 `qk.job(jobId)` |
| `storyboard.updated` | `qk.storyboard(id)`、`qk.project(id)` |
| `output.created` | `qk.project(id)`（嵌套 outputs）、`qk.storyboard(id)`（分镜状态联动） |
| `export.updated` | `qk.exports(id)`、`qk.project(id)` |
| `provider.updated` | `qk.providers` |

- REST 是真相：任何事件丢失/乱序不影响正确性；SSE 只负责"该重新查询了"。

## 9. 状态管理

- **服务端状态**：100% TanStack Query，组件不缓存业务数据副本。
- **URL 状态**：`stage`、选中分镜 `item`、灯箱 `output`（search params）——刷新/分享可恢复。
- **组件状态**：表单、勾选集（生成选择、审核批量）、抽屉开关，React state。
- 推导式阶段进度（见第 5 节）为纯函数 `deriveStage(projectDetail)`，单测覆盖。

## 10. 性能预算与工程纪律

| 指标 | 预算 | 手段 |
| --- | --- | --- |
| 首屏 JS | ≤ 350KB gzip | 路由级 `React.lazy`；antd v6 按需；motion 仅工作台页加载 |
| 字体 | ≤ 200KB，`font-display: swap` | 子集化自托管 |

| 渲染 | 网格 >200 项时虚拟化（`@tanstack/react-virtual`，届时再加依赖） | 首版数据量小，先不做 |
| 构建 | `pnpm build` 零 TS 错误；`vite build` sourcemap 开启 | strict + `noUncheckedIndexedAccess` |

## 11. 测试策略

- **单元/组件**（Vitest + Testing Library + msw，jsdom）：msw handlers 严格按 openapi.yaml 手写，每个特性模块一组。
- 关键用例清单（随阶段落地）：
  1. `lib/cost.ts`：UNKNOWN/null/缺字段/异常对象 → 恒定文案"费用由 Provider 决定，当前无法预估"；合法金额 → 正确格式化。
  2. 错误中间件：七种 code → `ApiError` 字段完整。
  3. SSE 映射：六个事件名 → 精确的失效 key 集合；未知事件不动作；不读 payload。
  4. 指纹：同输入乱序 itemIds → 同指纹；不同 revision → 不同指纹。
  5. 分镜确认：409 → 触发 refetch + 冲突提示；成功 → 锁定编辑。
  6. 生成确认弹窗：数量恒等于勾选项数；费用区对 UNKNOWN 的渲染；确认提交 body 含显式 `storyboardItemIds`。
  7. 审核：乐观更新与失败回滚；REJECTED 不计入导出候选。
  8. 上传：角色/变体归属带入 FormData 字段名与契约一致（`file/role/variantId`）。
  9. `deriveStage` 纯函数全分支。
  10. `prefers-reduced-motion` 下动效组件不抛错并即时呈现（MotionConfig 包裹测试）。
- **契约守卫**：`gen:api` 输出入库，PR diff 即契约同步检查。
- **e2e**：首版不做浏览器 e2e；以后端 `pnpm test:e2e:mock` 为链路保障，前端联调用真实后端手动验收清单（12 节）。
- 每阶段交付前：`pnpm --filter @ecomgen/web build && pnpm --filter @ecomgen/web test`；里程碑前根目录 `pnpm build && pnpm test`。
