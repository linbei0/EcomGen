# 电商套图流程重构方案

## 1. 方案状态

本文档记录已确认的新产品流程，作为后续产品、前端、API、Worker 和测试改造的统一依据。

本方案不启用 SKU 变体模型，不要求用户理解 `PRODUCT_TRUTH`、`STYLE_REFERENCE` 等内部素材角色，也不改变 `packages/ecom-skill` 作为模板与 Prompt 合约来源的定位。

## 2. 已确认决策

- 产品图和参考图是两类用户可见素材。
- 产品图用于还原商品本身，是生成商品主体的主要依据。
- 参考图用于风格、构图、包装或氛围参考，不能被当作用户商品事实。
- 用户不填写 SKU、颜色变体、尺寸变体或素材归属范围。
- 所有上传的产品图默认属于同一个商品。
- 第 1～5 步集中填写，Agent 在用户提交后生成整套分镜和提示词。
- Agent 只负责规划，不自动提交生图。
- 用户确认或编辑分镜后，才允许批量生图。
- 每个已选出图类型生成 1～N 张候选图。
- 分镜确认与生图操作合并，不重复确认同一批分镜。
- 生成结果、审核和导出合并为一个结果工作区。
- 支持单张下载、多选下载和全部下载。
- 卡片显示中文名称，不显示 `hero-image`、`flat-lay` 等内部模板 ID。
- 生成中只显示明确状态，例如“排队中”“生成中”“正在保存结果”；不显示没有 Provider 真实依据的百分比进度。

## 3. 用户主流程

```text
上传产品图与参考图
        ↓
填写核心卖点
        ↓
设置市场信息
        ↓
设置全局出图参数
        ↓
选择出图类型：AI 智能规划 / 用户手动选择
        ↓
Agent 生成中文分镜与可编辑提示词
        ↓
用户查看、编辑、删除、排序并确认分镜
        ↓
按图片类型和候选数量批量生成
        ↓
结果网格中查看、筛选、下载和导出
```

### 3.1 上传产品图与参考图

用户可以一次上传同一商品的多角度图片，例如正面、侧面、背面和细节图。角度越完整，模型越容易识别产品结构和材质。

上传区只暴露两个入口：

| 用户入口 | 作用 |
| --- | --- |
| 产品图 | 商品外观、颜色、Logo、结构、材质和可见细节的事实依据 |
| 参考图 | 风格、构图、包装、道具、光线或氛围的参考依据 |

参考图的具体用途由 Agent 自动判断。用户不需要选择内部素材角色。

系统必须在 Prompt 和生图输入中保持两类素材的语义边界：参考图中的竞品或其他商品不能被当作当前商品生成。

### 3.2 填写核心卖点

核心卖点支持手动填写和“AI 帮写”。输入内容用于：

- Agent 选择适合的图片组合；
- 生成每张分镜的画面目标和 Prompt；
- 生成卖点图或详情页图中的短文案；
- 约束不可证明的 claims，不得自动补充价格、规格、认证、疗效或物流承诺。

### 3.3 设置市场信息

市场信息集中设置，不散落在分镜卡片中。控件和当前项目契约的关系如下：

| 配置 | 首版控件 | 当前项目状态 | 用途 |
| --- | --- | --- | --- |
| 目标平台 | 多选下拉框 | 已支持 `DOMESTIC`、`AMAZON` | 影响平台留白、模板提示和导出目标 |
| 目标市场 | 下拉框或可搜索选择 | 当前没有独立字段 | 需要先定义市场枚举和 API 字段，不能直接伪装成已生效能力 |
| 文案语种 | 下拉框 | 当前没有字段 | 需要新增项目级语种字段后，才能约束 Prompt 和图片文案 |
| 视觉风格 | 下拉框 + 可选补充说明 | 当前由 `brandGuidelines` 和 Campaign Style Lock 承载 | 统一整套图片的色板、光线、背景和构图语言 |
| 品牌色 / 禁用元素 | 可选输入 | 已有 `brandGuidelines`、`prohibitedClaims` 等事实字段 | 约束视觉和文案，不允许 Agent 编造事实 |

当前可直接落地的市场配置只有平台选择和已有品牌/事实字段。目标市场、文案语种如果要成为真实生效的下拉框，必须同步加入项目类型、数据库、API、Agent 输入和 OpenAPI 契约；在契约完成前不应在 UI 中放置“看起来能用但不生效”的控件。

这些信息最终用于调整模特人种、场景氛围、构图习惯、文字语言、平台留白和视觉方向。

### 3.4 设置全局出图参数

全局参数在选择图片类型前设置：

| 参数 | 控件 | 说明 |
| --- | --- | --- |
| 生图模型 | 下拉框 | 选择当前已配置且支持生图的模型 |
| 分辨率 | 下拉框 | 例如 `1K`、`2K`、`4K`；选项由模型能力过滤 |
| 每类型出图数 | 步进器 | `−` / 当前数量 / `+`，最小值为 1，最大值由系统策略限制 |
| 图片比例 | 下拉框 | 例如自适应、1:1、3:4、4:3、16:9；选项由模型和模板能力过滤 |

当前 Provider 的模型能力契约尚未声明支持的分辨率和比例集合，因此这两个下拉框在实现前需要补充 Provider 能力描述或项目级允许值；不能根据模型名称猜测能力。

桌面端采用两列紧凑布局，结构与下图一致：

```text
┌──────────────────────┬──────────────────────┐
│ 模型                 │ 分辨率               │
│ [Gpt-image-2     ▼]  │ [2K              ▼]  │
├──────────────────────┼──────────────────────┤
│ 每类型出图数         │ 图片比例             │
│ [ − ] [ 1 ] [ + ]    │ [自适应尺寸       ▼]  │
└──────────────────────┴──────────────────────┘
```

“图片类型数量”和“每个类型出图数”必须分开表达：

```text
图片类型：商品主图、场景图、细节图
每类型候选数：2
预期输出：每种类型生成 2 张候选图
```

最终数量由已确认分镜数、每个分镜的候选数量以及实际生成范围共同决定。前端不得展示无法由任务输入推导的精确费用或精确完成时间。

### 3.5 选择出图类型

提供两种互斥但可切换的模式：

#### AI 智能规划

Agent 根据产品图、参考图、核心卖点、市场信息、全局参数和 `packages/ecom-skill` 模板目录，自动选择一组有转化逻辑的图片类型。

常见中文类型包括：

- 商品主图；
- 场景化生活图；
- 细节微距图；
- 卖点信息图；
- 包装配件图；
- 使用步骤图；
- 对比图；
- 社交媒体素材；
- 促销海报/Banner。

#### 用户手动选择

用户通过图片类型画廊或加号添加类型，并可以删除和排序。模板 ID 只在内部传输，界面始终显示模板的中文 `name`。

## 4. Agent 分镜规划与确认

Agent 的输出是可编辑的分镜计划，不是生图结果。

每个分镜至少包含：

- 中文显示名称；
- 内部模板 ID；
- 图片用途；
- 画面目标；
- Prompt；
- 负面约束；
- 图片比例和分辨率继承值；
- 创意或主体保护模式；
- 使用的产品图/参考图说明；
- 风险提示；
- 排序；
- 候选数量。

分镜卡片点击后打开弹窗，不再使用固定右侧栏。弹窗允许用户：

- 编辑中文名称；
- 修改图片类型；
- 修改画面目标和 Prompt；
- 修改模式；
- 修改候选数量；
- 删除分镜；
- 调整排序；
- 查看风险提示和素材引用。

用户点击“确认分镜并生成”后，系统一次性提交已确认的分镜集合。不得再进入另一个页面重新勾选同一批分镜。

## 5. 批量生图

生成任务应从“一个分镜固定一张图”升级为“一个分镜按候选数量生成多个输出”。

每个输出必须保留其来源信息：

- 分镜 ID；
- 候选序号；
- 生图参数快照；
- 使用的产品图和参考图摘要；
- Prompt 快照；
- Provider 任务 ID；
- 文件 hash。

生成状态只表达可验证事实：

- 排队中；
- 生成中；
- 正在保存结果；
- 已完成；
- 生成失败；
- 已取消。

不再将 `5 / 30 / 80 / 100` 等 Worker 固定阶段值展示为真实进度。图片生成后逐张出现在结果网格中，并保留取消、重试和失败原因。

## 6. 结果、审核与下载

步骤 5 和步骤 6 合并为结果工作区。

结果网格按中文分镜名称分组，每个分镜下展示多个候选图。用户可以：

- 点击图片打开大图弹窗；
- 单张下载；
- 多选图片后下载；
- 一键选择全部图片并下载；
- 标记保留、淘汰或待审核；
- 对单张图片重新生成；
- 导出 ZIP。

导出 ZIP 默认包含图片和 `manifest.json`。Manifest 保留分镜、Prompt、生成参数、审核结果和文件 hash，便于追溯。

## 7. 页面结构

这里的“单页连续表单”不是把页面拆成上栏、中栏、下栏三个固定区域，而是一个**单栏纵向滚动页面**：用户从上到下完成配置，页面不出现固定右侧检视器。

```text
固定顶部：项目名 · API 状态 · 设置
              │
              ▼
单栏主内容（纵向滚动）
  1. 产品图 / 参考图上传
  2. 核心卖点 + AI 帮写
  3. 市场信息：平台 / 市场 / 语言 / 风格
  4. 全局出图配置：模型 / 分辨率 / 比例 / 每类型候选数
  5. 出图类型：AI 智能规划 / 手动添加 / 中文类型卡片
  6. 分镜卡片：确认前可编辑，点击卡片用弹窗查看详情
              │
              ▼
确认分镜并生成
              │
              ▼
结果视图（切换当前主视图）
  图片网格 / 审核 / 单张下载 / 多选下载 / 全部下载 / 导出
```

配置视图、分镜确认视图和结果视图在同一路由内按状态切换，不同时堆叠在页面上：

```text
配置视图 → Agent 规划完成 → 分镜确认视图 → 确认并生成 → 结果视图
```

用户可以返回上一步修改配置或重新规划，但不需要在另一套“生成、审核、导出”页面之间重复确认。分镜详情通过卡片点击后的 Modal 展示，右侧栏完全移除。

## 8. `packages/ecom-skill` 适配边界

`packages/ecom-skill` 继续作为模板目录、Prompt 合约、风格锁和反幻觉约束的唯一来源。

项目层负责：

- 收集产品图、参考图和用户描述；
- 将用户输入映射为 Skill 所需的视觉简报；
- 让 Agent 选择合法模板并生成分镜；
- 校验模板 ID、模板变体和 Prompt 合约；
- 将产品图与参考图分开传递；
- 批量调用 Provider 并保存每个输出。

不能把未知模板 ID 静默当成普通 Prompt，也不能让参考图替代商品事实图。

## 9. 后端与数据模型改造范围

以下是实现阶段必须同步评估的改造点：

1. 移除 `VariantRecord`、`variantId`、`variantScope` 和所有 SKU 归属校验。
2. 将素材用户语义简化为产品图 / 参考图；内部可以保留更细的参考用途，但不暴露给普通用户。
3. 规划输入增加统一表单信息和素材分类信息。
4. 规划输出增加中文显示名称、候选数量和引用素材摘要。
5. 生图请求增加分辨率、比例和候选数量，并纳入请求指纹。
6. Provider 适配器支持按候选数量生成，或由 Worker 按候选序号执行多次调用；具体方式以 Provider 能力为准。
7. 输出记录增加候选序号和生成参数快照，避免多个候选无法区分。
8. 生成任务改为批量任务或可追踪的分镜候选子任务，不能依赖前端重复提交多个单图任务。
9. 移除依赖固定百分比的前端进度展示，保留状态和输出数量。
10. 更新 `docs/openapi.yaml`、共享类型、数据库迁移、Worker、Provider 测试和 Mock E2E。

开发数据处于早期阶段时，优先使用一次性迁移或明确的数据重建，不保留 SKU 运行时兼容分支。

## 10. 验收标准

- 用户可以在一个连续页面完成前五步配置。
- 用户可以选择 AI 智能规划或手动选择图片类型。
- Agent 只生成分镜和提示词，不自动生图。
- 分镜卡片使用中文名称，点击卡片通过弹窗查看和编辑。
- 用户只确认一次分镜，确认后直接进入批量生图。
- 每个图片类型可以配置 1～N 张候选图。
- 所有候选图可以按分镜分组展示。
- 生成中不展示虚假百分比，只展示真实任务状态。
- 产品图与参考图语义分离，参考图不会被当作商品事实。
- 不再出现 SKU、变体归属和跨 SKU 校验。
- 支持单张下载、多选下载、全部下载和 ZIP 导出。
- 所有模板 ID 都能映射为中文显示名称。
- 相关 API 契约、数据库、Worker、Provider、前端测试和 Mock E2E 同步通过。

## 11. 暂不纳入本轮范围

- 自由画布或节点式编辑器；
- 用户自定义模板市场；
- 自动识别并拆分多个商品款；
- 跨商品批量任务；
- Provider 未提供的真实生成百分比；
- 用伪造成功结果掩盖 Provider 或素材错误。
